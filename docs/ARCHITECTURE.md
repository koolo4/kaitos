# Архитектура Kaitos

Kaitos — AI-редактор кода в браузере (аналог Cursor / Claude Code). Один экран:
панель файлов, редактор с вкладками, чат с ассистентом, терминал, строка состояния, палитра команд.

## Слои

```
index.html            статическая разметка всех панелей и модалок (id — публичный контракт)
css/base.css          переменные тем, каркас экрана, кнопки, статусная строка, адаптивность
css/components.css    дерево, вкладки, редактор, терминал, чат, модалки, палитра, тосты
js/app.js             точка входа: создаёт ctx, вызывает init* модулей, связывает их
js/dom.js             помощники: $, $$, el, escapeHtml, debounce, formatTime, toast
js/fs.js              виртуальная файловая система демо-проекта (в памяти)
js/editor.js          редактор: вкладки, нумерация строк, черновики, сохранение по Ctrl+S
js/tree.js            дерево файлов из ctx.fs.tree(), сворачивание папок
js/chat.js            панель ассистента (сейчас демо-ответы без сети)
js/terminal.js        виртуальный терминал: ls, cat, open, theme, model и др.
js/settings.js        настройки в localStorage: провайдер, модель, ключ, тема, шрифт
js/palette.js         палитра команд (Ctrl+K) и быстрый переход к файлам
js/llm.js             клиент моделей: Ollama и OpenAI-совместимые API, поток, отмена, проверка связи
js/prompts.js         системный промпт, сборка контекста (файл, выделение, история)
js/markdown.js        безопасный мини-markdown для ответов (код, списки, экранирование)
js/tools.js           инструменты агента: разбор правок файлов из ответа модели, защита путей
js/diff.js            построчный diff (LCS), сжатие контекста, HTML-предпросмотр правки
js/highlight.js       подсветка синтаксиса без зависимостей (js, css, html, json, md, sh)
js/api.js             клиент локального сервера файлов (/api через прокси Vite)
js/fs-remote.js       файловая система с диска: зеркало в памяти, запись в фоне
server/paths.js       защита путей (внутри проекта, без служебных папок)
server/files.js       файловые операции через node:fs
server/git.js         git через execFile: статус, diff, журнал, коммит
server/run.js         запуск команд: оболочка, таймаут 60 с, лимит вывода 200 КБ
server/watch.js       слежение за файлами (fs.watch, рекурсивно)
server/index.js       HTTP API: health, files, file (GET/POST/DELETE), changes
scripts/dev-all.mjs   одновременный запуск сервера и Vite
tests/e2e/*.yml       постоянные сценарии проверки интерфейса
tests/*.mjs           сквозные тесты в jsdom (интерфейс и клиент модели), запуск: npm test
```

## Общий объект ctx

`js/app.js` создаёт единственный объект `ctx` и передаёт его в каждый `init*`:

| Поле | Что это |
|---|---|
| `ctx.fs` | файловая система: `read`, `write`, `has`, `create`, `remove`, `list`, `listDir`, `tree`, `size` |
| `ctx.editor` | `open(path)`, `close(path)`, `save()`, `onChange(fn)`, `contentOf(path)`, `active`, `tabs` |
| `ctx.tree` | `render()`, `setActive(path)` |
| `ctx.chat` | `send(text)`, `clear()`, `messages` |
| `ctx.terminal` | `run(line)`, `clear()`, `print(text, kind)` |
| `ctx.settings` | текущие настройки (объект) |
| `ctx.settingsApi` | `open()`, `close()`, `save()` — модалка настроек |
| `ctx.palette` | `open()`, `close()` |
| `ctx.llm` | `chat({ messages, onToken, signal })`, `test()`, `setMock(fn)`, `clearMock()`, `isConfigured()` |
| `ctx.editor.refresh(path)` | перечитать файл из файловой системы после правки моделью |
| `ctx.editor.renderHighlight()` | перерисовать подсвеченный слой редактора |
| `ctx.storage` | `{ mode: 'disk' \| 'demo', files, name, reason }` — откуда берутся файлы |
| `ctx.api` | клиент сервера файлов (когда `storage.mode === 'disk'`) |
| `ctx.updateSettings(patch)` | изменить настройки, сохранить и применить |
| `ctx.toggleSidebar()`, `ctx.toggleTerminal()` | свернуть панели |

`window.Kaitos = ctx` — через это e2e-сценарии и консоль браузера обращаются к приложению.

## Фаза 2: нейросеть (сделано)

1. `js/llm.js` — провайдеры `ollama` (`/api/chat`, NDJSON) и `openai` (`/v1/chat/completions`, SSE),
   потоковая отдача токенов в `onToken`, отмена через `AbortSignal`, понятные ошибки
   (`network`, `http`, `no-provider`, `aborted`), проверка соединения `test()`.
2. `js/prompts.js` — системный промпт, контекст файла с обрезкой до 12 000 символов, история из 12 сообщений.
3. `js/chat.js` — настоящие ответы модели, потоковая отрисовка, кнопка «Остановить», ошибки с подсказками,
   демо-режим без модели.
4. `js/markdown.js` — блоки кода с копированием, списки, заголовки; весь текст экранируется.
5. `js/settings.js` — температура, предел токенов, «Проверить соединение».

## Фаза 3: инструменты агента (сделано)

Модель не просто советует — она предлагает правку файла, а приложение показывает её как diff.

1. **Протокол правки.** В ответе модели блок с языком `kaitos-write` и путём:

   ````text
   ```kaitos-write src/utils.js
   <полное новое содержимое файла>
   ```
   ````

   Протокол описан в системном промпте (`js/prompts.js`, `EDIT_PROTOCOL`).
2. **`js/tools.js`** — разбор блоков, нормализация путей, защита: абсолютные пути, `..` и выход за проект
   отклоняются ещё до применения; такие правки показываются с объяснением и без кнопки «Применить».
3. **`js/diff.js`** — построчный diff через LCS, сжатие неизменённых участков, подсветка добавленных
   и удалённых строк. Весь текст экранируется.
4. **`js/chat.js`** — карточка правки под ответом: путь, статистика `+N −M`, diff, кнопки «Применить»
   и «Отклонить». Применение пишет файл в `ctx.fs`, перечитывает открытый файл в редакторе и обновляет дерево.

## Фаза 4: подсветка синтаксиса (сделано)

- `js/highlight.js` — `highlight(code, lang)` и `detectLanguage(path)`. Один проход регуляркой по строке,
  без зависимостей: js/ts, css, html, json, md, sh. Весь текст экранируется, разметка — только
  `<span class="tok-…">`, поэтому подсветка не может внести HTML.
- Редактор рисует два слоя: `<pre id="editor-highlight">` под прозрачной `textarea`.
  Текст `textarea` прозрачный (`color: transparent`, `caret-color` видимый), прокрутка синхронизируется.
- Цвета токенов — в `css/components.css`, отдельные значения для тёмной и светлой темы.

## Фаза 5: настоящие файлы на диске (сделано)

- `server/` — HTTP API на `node:http` без зависимостей. `server/index.js` слушает только `127.0.0.1:5178`,
  маршруты `/api/health`, `/api/files`, `/api/file` (GET/POST/DELETE), необязательный токен `X-Kaitos-Token`.
- `server/paths.js` — единая точка проверки путей: абсолютные пути, `..`, выход за проект, служебные
  папки `.git`/`.justai`/`node_modules` отклоняются до касания диска.
- `server/files.js` — список/чтение/запись/создание/удаление, лимит 2 МБ, только текстовые расширения.
- `js/api.js` — клиент с таймаутами и понятными ошибками (`network`, `auth`, `http`).
- `js/fs-remote.js` — **зеркало**: при старте проект читается в память, поэтому весь синхронный код
  (редактор, дерево, чат, diff) работает без переписывания; запись сразу меняет память и в фоне уходит на сервер.
- `vite.config.js` проксирует `/api` на 5178 — браузер не знает про CORS и порт.
- Индикатор в строке состояния: «диск: <проект>» или «демо (в памяти)».

## Фаза 6: правки извне (сделано)

- `server/watch.js` — `fs.watch(root, { recursive: true })`, дебаунс 60 мс, буфер событий с растущим `seq`.
  Отслеживаются только текстовые файлы; служебные папки, точечные файлы и временные файлы Vite (`*.timestamp-*.mjs`) мимо.
- `GET /api/changes?since=N` — клиент спрашивает «что нового после отметки». Опрос вместо SSE: работает
  через прокси Vite, переживает перезапуск страницы и не держит соединение.
- `js/fs-remote.js` — `sync()` обновляет зеркало, `startSync({ intervalMs, dirty, onChange })` опрашивает раз в 1.5 с.
  Собственные записи (они есть в `pending`) и файлы с несохранёнными правками пропускаются — ввод не теряется.
- `js/app.js` — после события обновляются дерево и открытый файл (`editor.reloadFromDisk`), в терминал пишется
  «Изменено на диске: …», а пропущенные файлы отмечаются предупреждением.
- Проверено живьём: правка через `/api/file` появляется в приложении за 1.6 с (`tests/live.mjs`).

## Фаза 7: git (сделано)

- `server/git.js` — `execFile('git', [...])` без shell, таймаут 15 с, лимит diff 300 КБ.
  `status` (porcelain + ветка), `diff` (для неотслеживаемых файлов собирается вид «новый файл»),
  `log`, `commit` (`git add -A` + `-m`, подпись берётся из `KAITOS_GIT_NAME`/`KAITOS_GIT_EMAIL`).
- HTTP: `GET /api/git/status|diff|log`, `POST /api/git/commit`. Путь для diff проверяется тем же
  `guard.resolveInside`, что и файловые операции, поэтому `../…` отдаёт 400.
- `js/git.js` — панель в сайдбаре: ветка и число изменений, значки M/A/D/R/?, diff по клику,
  поле сообщения и «Закоммитить» (Ctrl+Enter). В демо-режиме панель скрыта, без репозитория — честно
  пишет «проект не под git» и блокирует кнопку.
- Проверено в настоящем репозитории: 15 проверок (`tests/git.mjs`), включая коммит и отказ в обычной папке.

## Фаза 8: команды на сервере (сделано)

- `server/run.js` — `spawn(shell, ['-c', command])` в папке проекта (на Windows — `cmd /d /s /c`),
  `KAITOS=1` в окружении, `PAGER=cat`, таймаут 60 с с `SIGKILL`, лимит вывода 200 КБ.
  Возвращает `{code, output, truncated, timedOut, durationMs}`; `code: null` означает «убита по таймауту».
- `POST /api/run {command}` — пустая команда даёт 400; `allowRun: false` выключает маршрут целиком.
- `js/terminal.js` — в режиме диска строка уходит на сервер, вывод печатается построчно, внизу —
  «готово за N мс» или код выхода; после команды обновляется git-панель. `help` и `clear` остаются локальными,
  `Ctrl+L` очищает. Без сервера работает прежний виртуальный набор команд.
- Это сознательно мощная возможность: сервер слушает только `127.0.0.1`, а при заданном `KAITOS_TOKEN`
  запросы без токена отклоняются. Интерфейс подсказывает это в приветствии терминала.

## Фаза 9: точечные правки (сделано)

- `js/tools.js` — второй протокол `kaitos-edit`: блок «НАЙТИ / ЗАМЕНИТЬ». `patchContent` заменяет
  единственное вхождение, прощает хвостовые пробелы и CRLF, а при нуле или нескольких совпадениях
  отказывает с понятным текстом. `patchesToEdits` превращает патч в обычную правку с готовым содержимым,
  поэтому карточка diff и «Применить» работают без изменений.
- `js/prompts.js` — модели предложены оба способа с явным правилом: не переписывать файл целиком ради
  одной строки. Причина конкретная: локальная `qwen3.5:9b` при перезаписи портит соседние строки (PR #60).
- `js/chat.js` — карточки строятся и из `kaitos-edit`, и из `kaitos-write`.

### Несколько правок одного файла (сделано)

`patchesToEdits` применяет правки последовательно: каждая следующая считается от результата предыдущей,
поэтому вторая правка не «не находит» фрагмент, изменённый первой. Если правка файла не применилась,
остальные правки этого файла помечаются «Пропущено», чтобы не переписывать файл частично.

`applyEdit` в `js/chat.js` пересчитывает точечную правку от **актуального** текста файла, а не от снимка
в карточке: порядок нажатий «Применить» больше не важен.
